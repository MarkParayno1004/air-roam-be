# Xendit → PayMongo

**Why:** the client already has a ready PayMongo account. **Goal:** replace Xendit completely; no order has ever been paid, so nothing is kept for Xendit. **Not goals:** own card form, refunds by API (staff refund in the PayMongo dashboard, as with Xendit), two providers side by side.

**Approaches:** (1) PayMongo hosted Checkout Session — closest to today, card data never touches us; chosen. (2) Own payment form with Payment Intents — card-security duties, more screens. (3) Keep Xendit and add PayMongo — double upkeep.

## Facts (docs.paymongo.com, read 2026-11-26)
- `POST https://api.paymongo.com/v1/checkout_sessions`, Basic auth (secret key as user, empty password). Body `{"data": {"attributes": {line_items: [{name, amount (centavos, int), currency "PHP", quantity}], payment_method_types, success_url, cancel_url, reference_number, description, metadata}}}`. Response `data.id` (cs_…), `data.attributes.checkout_url`.
- `GET /v1/checkout_sessions/{id}`: `data.attributes.payments[]`, each `attributes.status` ("paid") and `attributes.amount` (centavos); session `status` stays "active" when paid. `reference_number`, `metadata` echoed.
- `POST /v1/checkout_sessions/{id}/expire`. **A session never expires by itself and no event is sent on expiry.**
- Webhook event `checkout_session.payment.paid`: `data.attributes.type`, `data.attributes.livemode`, `data.attributes.data` = session (`id`, `attributes.reference_number`).
- Signature: header `Paymongo-Signature: t=<ts>,te=<hex>,li=<hex>`; HMAC-SHA256 of `t + "." + raw body` with the webhook secret; `te` for test mode, `li` for live (the other is empty). Must answer 200–209 with JSON within 30 s; up to 12 retries; duplicates possible.

## Design
- `payments/paymongo.py` (replaces `xendit.py`, the only module that talks to PayMongo): `create_checkout(order)`, `expire_checkout(order)`, `get_session(session_id)`, `paid_centavos(session)`. 10 s timeouts, raise on failure. One line item "Air Roam order <8 chars>" for `total_amount` in centavos (Decimal, exact, never float). `reference_number` = order id. Methods from `PAYMONGO_METHODS` (default `gcash,paymaya,qrph,card`; only methods enabled on the account may be listed). Success URL: today's redirect. Cancel URL (web): `/account/orders/<id>`, which has Pay now; app: the deep link, as today.
- `payments/settle.py`: one function used by the webhook and the job. Under `select_for_update`: same payment already handled (`received_centavos`, the amount last handled for the order's session) → no-op; pending + exact amount → paid (and bookings confirmed); any other money (wrong amount, order cancelled/expired/refunded/fulfilled, or marked paid by staff) → `needs_attention` with a note naming the PayMongo session and what to do, logged; never silently dropped. A soft-deleted order is restored, settled or flagged as above, and always flagged as a deleted order that was paid. A repeat of the same event changes nothing.
- Leaving pending: traveler cancel and staff status changes (row-locked) close the PayMongo session after the lock. If closing fails the change still stands and is logged; the traveler's cancel also flags the order. A staff change that loses the race to a payment gets 409 and changes nothing. Staff can't delete a pending order (409, "Cancel the order first.").
- Webhook `POST /api/v1/payments/paymongo/webhook`: verify signature on the raw body (constant time; `te` when the secret key is `sk_test_`, else `li`; empty or missing → 403; no configured secret → 403; each rejection logged without header or body). Other event types → 200 ignored. Then **re-fetch the session from PayMongo** and use that, not the body; unreachable PayMongo, or a session it reports as unpaid → 503 so it retries. The order must be the one whose `payment_session_id` is that session AND whose id equals the fetched `reference_number`; otherwise 404.
- Command `expire_unpaid_orders` (`--hours`, default 24), run by the host's scheduler (hourly): each old pending order → expire the session, re-fetch; paid → settle; unpaid and closed → expired; still open → left pending and logged. One failing order is logged and doesn't stop the others. Orders without a session are expired directly.
- Order fields renamed: `xendit_invoice_id` → `payment_session_id`, `xendit_invoice_url` → `payment_url` (rename migration, data kept); `received_centavos` added (internal, not in the API). API follows; checkout response keeps `invoice_url`.
- Settings/env/README: `PAYMONGO_SECRET_KEY`, `PAYMONGO_WEBHOOK_SECRET`, `PAYMONGO_METHODS`; the Xendit ones go.
- Store/admin copy: "Pay with Xendit" → "Pay securely"; other mentions → PayMongo.
